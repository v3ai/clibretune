# Bundled ECU definitions

clibretune ships with a library of ECU definitions (TunerStudio-format INI files), so that a
connected ECU gets the right definition automatically and without a network connection
(`src/project/inidb.h`). The files are third-party works, embedded **unmodified**: packed
losslessly into `src/project/inidb_data.c` by `tools/gen_definitions.py`, and each one unpacks
byte for byte (checked against its size and CRC-32 at run time, and its sha256 in the manifest
when the library is generated; `tests/test_inidb.c` checks every file).

The INI files themselves are not kept in git (about 110 MB). Each family folder has a
`sources.json` manifest that records, for every file, where it comes from (URL, member inside the
release zip, tag or tags, commit), its size, sha256, signature and licence.

| Family | Folder | What | Files | Licence |
|--------|--------|------|-------|---------|
| Speeduino | `speeduino/` | `reference/speeduino.ini` of every release tag from 201712 to 202501.7 (39 tags; point releases with an identical INI share one file) | 31 | GPL-2.0-or-later |
| rusEFI | `rusefi/` | `rusefi_<board>.ini` from every board bundle of the releases release_20260812 (latest stable, 47 boards), release_20260220_2 (39) and release_20251018 (37) | 123 | GPL-3.0 + the rusEFI additional terms |
| FOME | `fome/` | `fome_<board>.ini` from every board bundle of release_260501_02 (latest) | 12 | GPL-3.0 + the same terms |
| miata-ecus | `miata-ecus/` | `rusefi_miata-ecu.ini`, the artifact of the Firmware workflow run 44696916909 (commit 17c525dbdc) | 1 | GPL-3.0 (see below) |

## Licences, and what they mean for clibretune binaries

- **Speeduino** (https://github.com/speeduino/speeduino), by Josh Stewart and contributors:
  GPL-2.0, and the source files say "version 2 of the License, or (at your option) any later
  version". Compatible with clibretune's own GPL-2.0-or-later.
- **rusEFI** (https://github.com/rusefi/rusefi), by rusEFI LLC and contributors: GPL-3.0, with
  the additional terms of its `license.txt` (notices that the firmware is for off-road and
  racing use). The INI files are generated by the rusEFI build and released in each board bundle.
- **FOME** (https://github.com/FOME-Tech/fome-fw), a rusEFI fork by the FOME contributors:
  GPL-3.0 with the same additional terms (`LICENSE`).
- **miata-ecus** (https://github.com/v3ai/miata-ecus): the repository's board files are MIT, but
  the INI is generated by the rusEFI build it pulls in, so it is a rusEFI work and GPL-3.0.

**GPL-3.0 implication.** clibretune's source is GPL-2.0-or-later, but a binary that contains the
rusEFI, FOME or miata-ecus files is a combined work that can only be distributed under
**GPL-3.0** (the "or later" of clibretune's licence allows that; GPL-2.0-only terms would not).
Whoever distributes such a binary must offer the corresponding source under GPL-3.0, which this
repository is. To build a binary that stays under GPL-2.0-or-later, regenerate the library with
the Speeduino files only:

    python3 tools/gen_definitions.py --only speeduino

## MegaSquirt: not bundled

MegaSquirt INI files (MS2/Extra, MS3) are not included. The MS3 INI carries "Copyright 2007..2010
James Murray and Kenneth Culver" with no licence or redistribution grant, and the community
collections of MegaSquirt INIs have no licence either. Without a grant from the copyright holders
they cannot be redistributed; MegaSquirt users keep using the INI that comes with their firmware
(or "Search Online").

## Regenerating

    python3 tools/fetch_definitions.py --discover   # ask GitHub what the pinned tags/releases hold,
                                                    # rewrite the sources.json manifests
    python3 tools/fetch_definitions.py              # download the listed files to build/definitions/
                                                    # (sha256 checked; GITHUB_TOKEN or `gh` login
                                                    # needed for the Actions artifact)
    python3 tools/gen_definitions.py                # src/project/inidb_data.c (about a minute)
    python3 tools/gen_definitions.py --check        # is the committed data up to date?
    python3 tools/gen_definitions.py --extract      # recover the files from the committed data

What is bundled is pinned at the top of `tools/fetch_definitions.py` (Speeduino: first tag;
rusEFI and FOME: release names; miata-ecus: workflow run). To move to a newer rusEFI release, put
it first in the list (and drop the oldest), then run the three commands. GitHub Actions artifacts
expire after 90 days; `--extract` keeps the committed miata-ecus file reproducible after that.

## ECU signatures

| Family | Example | Matching |
|--------|---------|----------|
| Speeduino | `speeduino 202501` | one signature per release month; point releases share it (the newest file wins) |
| rusEFI | `rusEFI master.2026.08.13.proteus_f4.357168325` | branch, build date, board, hash of the configuration; custom boards build from `main` |
| FOME | `rusEFI (FOME) .2026.06.03.atlas.3685778166` | as rusEFI, never matched against rusEFI files |
| miata-ecus | `rusEFI main.2026.11.20.miata-ecu.282710243` | as rusEFI |

When no file has the ECU's exact signature, `lt_inidb_resolve()` offers the nearest build of the
same family and board (closest date; for Speeduino the closest release month) as a "near" match,
which the program uses with a warning and a "Find Exact INI..." action.
